# Writing

Write for the reader's decision. Lead with the outcome, then evidence and material
tradeoffs. Use plain language, connected short paragraphs, and lists for genuinely
parallel items. Remove filler, praise, repeated conclusions, and inflated claims.

For review descriptions, explain the problem and resulting behavior, then actual
validation. Follow the repository's template. Avoid a chronological tool diary.

Keep comments for non-obvious reasons and constraints that code cannot express.
Prefer clearer names and types over explanatory narration. Preserve useful public
API documentation, license notices, and tool directives. Do not delete those merely
to achieve fewer comments. Check that tightening prose did not remove uncertainty,
exceptions, or evidence the reader needs.
