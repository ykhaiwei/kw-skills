# Prototype

1. Name the decision this experiment must settle. If the user wants a production
   feature with an established direction, use [feature](feature.md).
2. Gather relevant references when the design space is open. Use the smallest
   isolated scratch artifact that can demonstrate the alternatives.
3. Compare structurally or visually different variants using
   [arena](../workflows/arena.md) where useful. Label them clearly; use one switcher
   for a visual comparison when practical.
4. Observe each variant on the matching surface. Record screenshots, timings, or
   actual output. Prototype quality is judged by what the experiment can establish.
5. Present the alternatives, evidence, tradeoffs, and recommendation. Identify the
   scratch path and limitations. Move to production implementation only within the
   user's requested scope, through [feature](feature.md).

Reply with the decision and evidence. Label the artifact as a prototype.
